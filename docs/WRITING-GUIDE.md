# 팁픽(TIP-PICK) 글 작성 양식 가이드 (SSOT)

> **이 문서의 목적**: 어떤 툴(코워크·안티그래비티 챗·기타 AI)에서든, 집·회사 어디서든
> 이 문서 + `docs/HANDOVER.md`만 읽으면 **기존 글 양식/형식/규칙을 벗어나지 않고** 글을
> 작성할 수 있다. "오늘 ○○ 글 1편 써줘"라고 하면 아래 양식을 그대로 따른다.
>
> 최종 갱신: 2026-07-14 | 도메인: tip-pick.com | 어떤 툴에서든 복붙 시작 프롬프트는 §8
> ⭐ **최우선 규칙 = §1-6 원본성 필수 요소** — 자체 계산 예시 없는 글은 발행 금지(신규·보강 공통).

## 1. 블로그 글 (.md) — 가장 자주 쓰는 형식

**파일**: `src/content/posts/YYYY-MM-DD-english-slug.md` (날짜 = 작성일, slug = 영문 케밥)

### 1-1. 공통 frontmatter (모든 글)
```yaml
title: "..."        # ≤ 35자. 에버그린(시점성 표현 금지). 핵심 키워드 앞쪽.
date: YYYY-MM-DD
summary: ...        # 1~2문장
description: ...    # ≤ 90자, 검색 노출용
category: 경제      # ⚠️ "경제" 또는 "benefit" 둘 중 하나만! (아래 1-4)
tags: [키워드, ...]
officialCurationNote: "..."   # ⭐ 에디터 한마디(상세 페이지 상단 박스에 노출)
```

### 1-2. 경제 글 (`category: 경제` → /money)
본문 **의미 뼈대**(순서·역할은 유지, **H2 문구는 글마다 주제에 맞게 변주** — 2026-07-20 개정, §1-7 참조):
```
(도입 2~3문단 — 검색 질문에 숫자로 즉답)
## [비교/요약 표 섹션]   ← 표 1개 이상. 라벨은 글 맞춤(예: "고정 vs 변동, 숫자로 비교")
## [핵심 섹션들]
## [FAQ 섹션]           ← 라벨 변주(예: "갈아탈 때 자주 나오는 질문")
## [마무리 섹션]         ← 내부링크 루프(형제 글·계산기·/money). 라벨 변주
(면책 한 줄: 2026년 기준, 공식 확인 안내)
```
표준 예시: `2026-06-28-stress-dsr-loan-limit-2026.md`, `2026-07-13-health-insurance-dependent.md`

### 1-3. 지원금 글 (`category: benefit` → /benefits)
지원금 글은 상세 템플릿이 **공식정보 블록**을 렌더하므로 `official*` 필드를 채운다.
```yaml
# (공통 frontmatter에 더해)
officialTarget: 만 65세 이상 ...        # 대상
officialDetails: ...                     # 한 줄 개요
officialRequirements: ["조건1", "조건2", "조건3"]
officialHowToApply: ["신청처1", "신청처2"]
officialTip: "..."
officialDeadline: 상시                    # ⭐ 상시 사업이면 반드시 "상시"(에버그린). 진짜 마감 있을 때만 날짜.
officialEligibilityQuiz: []               # ⭐ 빈 배열이면 '1분 자격진단' 위젯 미표시(기본). 켜려면 질문 배열.
link: "https://www.bokjiro.go.kr"        # 공식 신청 사이트
```
본문 **의미 뼈대**(순서·역할은 유지, **H2 문구는 글마다 주제에 맞게 변주** — 2026-07-20 개정, §1-7 참조):
```
(도입 2~3문단 — 검색 질문에 숫자로 즉답)
## [요약 표 섹션]        ← 표. 라벨은 글 맞춤(예: "월 30만 매칭, 한눈에 정리")
## [자격 섹션]           ← 대상·소득/재산 조건(예: "2026년에 좁아진 자격")
## [금액 섹션]           ← 금액·직접 계산(예: "얼마나 받나 — 직접 계산해 봤습니다")
## [신청 방법 섹션]
## [FAQ 섹션]            ← 경계 사례 문답(예: "애매한 경우 — 부모와 같이 살면?")
## [마무리 섹션]          ← 내부링크 루프(/benefits·관련 글)
(면책)
```
표준 예시(이 양식의 기준): **`2026-07-20-youth-tomorrow-savings-account-guide.md`**, **`2026-05-29-youth-savings-mirae-vs-doyak-guide.md`**

### 1-4. ⚠️ category 규칙 (중요)
- **`경제` 또는 `benefit`만 쓴다.** `정보`·`benefits`·`가이드` 같은 값은 쓰지 말 것(매핑/라벨 꼬임).
- (과거 `정보` 글은 2026-07-02 전량 `benefit`으로 통일 완료 → 현재 두 값만 존재. 신규도 두 값만.)

### 1-5. 절대 금지 / 필수
- ❌ `image`·`ogImage`·`originalTitle` 필드 넣지 말 것(미사용 잔재. 썸네일은 카테고리 색 자동).
- ❌ 지역명·운영자 이름·"공공데이터" 문구.
- ❌ 시점성 표현("곧 출시", "마감 임박", "이번 달") → **에버그린**으로. 제목·summary·description(검색 노출면)에는 재촉·낚시 어투("서두르세요", "놓치지 마세요!") **절대 금지**, 본문에서도 지양.
  - ⚠️ **(2026-08-06 단서 추가) 금지 대상은 '문구'이지 '주제'가 아니다.** 마감이 있는 사업·캠페인도 다룬다 — 다만 "이번 달", "마감 임박" 대신 **"○년 ○월 ○일까지"처럼 절대 날짜로 쓰고**, 본문에 확인일과 출처를 명시한다. 이 규칙을 '기한 있는 지원금은 우리 주제가 아니다'로 확대 해석해 **실제 수요가 큰 시의성 주제를 통째로 놓친 사례가 있었다**(2026-08-06 민생회복 소비쿠폰 — 사이트 내 관련 콘텐츠 0건).
- ✅ 수치·사실은 공식 자료로 확인, 불확실하면 단정 금지.
- ✅ 내부링크 루프(글→글, 계산기, 카테고리) 필수 — 마무리에 형제 글 1~2 + 본문 맥락 링크.

### 1-6. ⭐ 원본성 필수 요소 (2026-07-14 신설 — 최우선 규칙, 신규 글·기존 글 보강 공통)
> **배경**: 애드센스 5차 거부(5회 연속 "가치가 별로 없는 콘텐츠")의 실원인 중 하나가 '공식 자료 재정리 + 균일 템플릿 대량 발행'. 공식 자료를 옮겨 적은 글은 발행하지 않는다. **모든 글에 "다른 데 없는 조합"을 직접 만들어 넣는다.**

모든 신규 글·보강 글에 아래 **①은 무조건 + ②~④ 중 최소 1개(권장 2개)** 포함:

1. **① 자체 계산 예시 (필수)** — 구체 인물 설정(소득·가구원수·상황)에 실제 수치를 대입해 **직접 계산·검산한 예시** 1개 이상. "공시 5억 1주택이면 연 62만 원(7·9월 각 31만)"처럼 숫자가 나오는 문장. 계산기 있는 주제면 계산기 로직과 값 일치 필수.
2. **② 상황별 시나리오** — "퇴사 직후라면 / 은퇴 앞뒀다면 / 프리랜서라면" 식 분기별 첫수를 표나 리스트로. 독자가 자기 케이스를 바로 찾게.
3. **③ 자체 조합 비교표** — 공식 페이지에 없는 교차 비교(제도 vs 제도, 유형 vs 유형, 경계값 전후). 공식 표 옮겨 적기는 해당 안 됨.
4. **④ 경계 사례 FAQ** — 검색해도 바로 안 나오는 "애매한 케이스" 문답 1개 이상(원칙+예외 구조. 예: "부부 중 한 명만 기준 초과면?").

- 본문 맥락에서 **우리 계산기·가이드로 "직접 확인" 유도** 1회 이상(마무리 링크와 별개).
- 보강 작업도 같은 기준: 오래된 글에 ①부터 채우고 ②~④ 중 빠진 것 추가. **보강 글과 신규 글의 완성 기준은 동일하다.**
- 게이트 통과와 무관하게, ①이 없으면 발행하지 않는다.

### 1-7. ⭐ 구글 친화 스타일 규칙 (2026-07-20 신설 — 전면 검수에서 도출, 신규·수정 공통)
> **배경**: 2026-07-20 전 콘텐츠(글 78·가이드 16·계산기 18) 전수 검수 결과, 애드센스 "저품질" 판정을 부르는 반복 패턴이 확인됨. 아래는 운영자 확정 규칙.

1. **H2 문구 변주 (운영자 확정, 2026-07-20)** — 의미 뼈대(요약→자격→금액→신청→FAQ→마무리)는 유지하되, `한눈에 요약`·`누가 받나`·`마무리` 같은 **고정 라벨을 그대로 복사하지 않는다.** 글마다 주제·핵심 수치가 드러나는 고유 문구로 쓴다. (같은 라벨이 수십 편에 반복되면 구글이 '대량 템플릿 발행'으로 봄)
2. **도입 즉답** — 첫 2문단 안에 검색자의 질문에 **구체 숫자로** 답한다. "~가 궁금하시죠", "13월의 월급이라는 말이" 같은 상투 도입·일반론 배경 설명으로 시작하지 않는다.
3. **고정 블록 금지** — "💡 팁픽 에디터 인사이트" 같은 **동일 라벨 블록을 여러 글에 복사하지 않는다.** 인사이트·팁은 그 글 고유의 소제목으로 녹인다.
4. **마무리 상투문 변주** — "다른 지원 제도는 정부 지원금 전체에 모아 두었습니다"처럼 여러 글에 똑같은 문장을 쓰지 않는다(링크는 유지, 문장은 글마다). 면책 문구만 예외적으로 통일 허용.
5. **모호 수치 금지** — "수십만 원", "10%대", "수백만 원 단위"로 얼버무리지 않는다. 산술 예시(글 안 수치 조합 또는 "연 4%로 가정" 명시)로 원 단위까지 보여준다.
6. **FAQ 회피 답변 금지** — "고객센터·공식 사이트에서 확인하세요"로 끝나는 문답을 만들지 않는다. 원칙+예외로 직접 답하고, 확인 불가한 부분만 정직하게 안내한다.
7. **자매 글 차별화** — 같은 주제군 글과 도입 패턴·구성·문장이 겹치지 않게 쓰고, 겹치는 내용은 상세 글로 링크하고 압축한다. 같은 키워드를 정면으로 노리는 글을 새로 만들지 않는다(카니벌라이제이션).

### 1-8. ⭐ 키워드 규칙 (2026-08-06 신설 — 운영자 지시, §1-6과 함께 최우선)
> **배경**: 애드센스 거절 사유 중 하나가 트래픽. 경쟁에서 클릭을 받으려면 **사람들이 실제로 치는 말**이 제목에 있어야 한다. 2026-08-06 전수 점검 결과, 우리 제목은 인사이트 중심으로 잘 쓰였지만 **검색어와 어긋난 것이 다수** 확인됐다(예: `장기요양 본인부담금` vs `요양원 비용` = **24배 차이**).

**발행 전 반드시 이 순서로 확인한다.**

1. **후보 2~3개를 뽑는다** — ⓐ 제도 공식명(본인부담상한제·근로장려금·실업급여) ⓑ 생활어(요양원 비용·병원비 환급·숨은 돈 찾기) ⓒ 우리가 쓰려던 표현.
2. **네이버 데이터랩으로 상대 검색량을 비교한다**(`datalab_search`, timeUnit=month, 최근 3개월).
   - ⚠️ **모든 배치에 고정 기준어 `실업급여`를 넣는다.** 데이터랩은 요청 내부에서만 최대 100으로 정규화하므로, 기준어가 없으면 배치 간 비교가 불가능하다.
   - ⚠️ 오타가 나면 결과가 빈 배열로 나온다. **빈 결과 = 검색량 0이 아니라 오타 의심**부터 할 것(2026-08-06 `디딩돌대출`·`무더위쉬터`로 실제 오판).
3. **가장 큰 것을 제목 앞부분에 그대로 넣는다.** 조어·설명형 금지(`중장년지원금`·`여름지원금`·`노후복지`·`미청구 국민연금` 같은 말은 아무도 검색하지 않는다).
4. **그 키워드를 네 곳에 반복한다** — 제목 앞부분 · `description` · **도입 첫 문단** · H2 하나 이상.
5. **`tags[0]`은 반드시 실제 검색어**로 쓴다(태그는 조어 창고가 아니다).
6. **클러스터·주간 주제를 정할 때도 같은 검증을 한다.** 2026-08-02에 "숨은 내 돈 찾기" 5클러스터를 검색량 확인 없이 확정했다가, 나중에 보니 `경정청구`만 크고 나머지는 0.06~13 수준이었다.

### 1-8-2. ⭐ 제목 2절 공식 (2026-08-06 신설 — 애드센스 승인 사이트 벤치마크에서 도출)
> **배경**: 2026-08-06 운영자 지시로 애드센스 승인 지원금 사이트(awoo.or.kr)를 전수 분석. 제목 구조가 우리와 달랐다. 우리는 **1절(검색어 — 설명)**, 저쪽은 **2절(검색어+숫자, 사용자 행동)**이다. 2절이 롱테일 조합을 훨씬 많이 잡는다.

**공식: `[검색 키워드] [숫자·날짜], [사용자가 하려는 행동]`**

| | 나쁨(우리 기존) | 좋음(새 공식) |
|---|---|---|
| 예1 | 국민연금 반환일시금 — 청구 시효 5년과 10년 | 국민연금 반환일시금 시효 5년, 지나면 못 받는 경우 |
| 예2 | 요양원 비용 얼마 — 장기요양 등급별 본인부담금 | 요양원 비용 월 186만 원, 등급별 본인부담금 계산 |
| 예3 | 숨은 돈 찾기·미환급금 조회 — 창구 6곳 시효 | 숨은 돈 찾기 창구 6곳, 시효 지나기 전 조회 순서 |

**규칙 5개**

1. **맨 앞은 §1-8로 실측한 검색 키워드 그대로.** 조어·수식어를 앞에 두지 않는다.
2. **1절에 숫자를 넣는다** — 금액·기간·건수·날짜·배율 중 하나. 숫자 없는 제목은 클릭률이 떨어지고, 우리 글의 §1-6 자체 계산이 제목에서 안 보인다.
3. **구분자는 쉼표(`,`)** — 대시(`—`)는 뒤가 '설명'처럼 읽히지만 쉼표는 뒤가 '두 번째 검색 문구'로 읽힌다. **기존 대시 제목은 전부 교체 대상.**
4. **2절은 반드시 독자의 행동·상황어**로 끝낸다 — `~ 안 나올 때`, `~ 신청 순서`, `~ 못 받는 경우`, `~ 계산`, `~ 확인 방법`, `~ 조건`. 제도 설명어(`~ 총정리`, `~ 알아보기`, `~ 완전정복`)는 금지.
5. **32자 이내.** 넘으면 검색결과에서 2절이 잘려 공식이 무의미해진다.

⚠️ **제목을 바꿔도 URL은 바뀌지 않는다**(슬러그 = 파일명). 리다이렉트 불필요.

### 1-8-3. ⭐ 질문형 H2 규칙 (2026-08-06 신설 — 같은 벤치마크)
> 승인 사이트는 본문 H2를 **독자가 검색창에 그대로 치는 문장**으로 쓴다. 예: `근로장려금이 8월 27일에 안 들어왔어요, 먼저 뭘 확인하나요?` / `근로장려금이 안 들어오는 원인 5가지는 무엇인가요?`

- **각 글의 본문 핵심 H2 중 최소 3개를 질문형으로** 쓴다(전부는 아니다 — 표·요약·마무리 섹션은 서술형 유지).
- 질문형 H2에는 **헤드 키워드를 그대로 넣는다.** "이건 어떻게 하나요?" 같은 대명사 질문은 키워드가 사라져 무의미하다.
- 효과 3가지: ⓐ 키워드가 H2마다 반복돼 주제 신호가 강해진다 ⓑ 검색 문장과 정확히 일치해 스니펫에 뽑힌다 ⓒ AI 답변엔진(ChatGPT·Perplexity)이 그대로 인용한다.
- §1-7 1번(H2 변주)과 충돌하지 않는다 — **질문 문장에 그 글의 고유 수치·상황을 넣으면** 자동으로 글마다 달라진다. H2 전체 중복은 계속 0을 유지한다.

### 1-9. ⭐ 글 구조 표준 (2026-08-06 신설 — answer-first)
> 승인 사이트 글의 뼈대. 우리 글(2,500~3,000자)보다 3배 길고(8,500~9,000자), **첫 문장에 답이 전부 들어 있다.**

**신규 글은 아래 순서를 기본형으로 한다.**

1. **한 줄 정답 (필수·신설)** — 도입 **첫 문장 하나**에 결론을 전부 담는다. 조건·금액·행동이 한 문장에 들어가야 한다.
   > 예: "근로장려금 정기분은 2026년 8월 27일 본인 명의 계좌로 입금되며, 안 들어왔다면 홈택스 심사진행상황 조회로 계좌 오류·체납 차감·감액·심사 지연 여부를 먼저 확인하세요."
   - §1-7 2번(도입 즉답)의 강화판이다. 두 문단이 아니라 **한 문장**.
2. **비교/요약 표** — 기존과 동일(§1-6 ③).
3. **본문 H2 3~5개** — 이 중 3개 이상 질문형(§1-8-3).
4. **자체 계산** — §1-6 ① 필수. ⚠️ **승인 사이트에는 자체 계산이 없다. 이건 우리만의 차별점이니 절대 빼지 않는다.**
5. **FAQ 5건** — 기존 3~4건에서 **5건으로 상향**. 경계 사례 1건 이상 포함(§1-6 ④).
6. **마무리 내부링크 루프** — 기존과 동일.
7. **원문 출처 (필수·신설)** — 글 맨 끝에 `## 확인한 자료` 섹션. **3건 이상**, 각 항목은 `기관명 · 확인일 · 문서 제목` 형식. 링크가 있으면 함께.
   > 예: `- 국민연금공단 · 2026-08-06 확인 · 「반환일시금 청구 안내」`
   - 이유: 우리는 그동안 본문에 근거를 녹여 쓰기만 했다. **출처를 눈에 보이게 모아 두는 것이 E-E-A-T 신호**이고, 애드센스 심사에서 '정보 안내 사이트'로 인식되는 데 유리하다.
   - ⚠️ 확인하지 않은 자료를 적지 않는다(AGENTS.md 4). 실제로 본 것만.

**분량 기준 상향**: 신규 글 **5,000자 이상**(기존 2,500~3,000). 늘리는 방법은 **문장 늘리기가 아니라 ① 자체 계산 시나리오 추가 ② 질문형 H2 추가 ③ FAQ 5건 ④ 출처 섹션**이다. 물타기 문장으로 채우면 §1-7 위반이다.

## 4. 공통 기술 규칙 (반드시 지킬 것)

- ⚠️ **`.tsx`·`.ts` 파일은 Edit·Write 도구로 만들지/고치지 말 것** → NUL 바이트가 섞여 깨진다(TS1127). **Python으로만** 쓴다:
  `open(path, "w", encoding="utf-8", newline="\n").write(content)` (신규) /
  기존 수정은 `open(path, encoding="utf-8", newline="").read()` → 문자열 치환 → 같은 방식 저장.
  기존 파일이 깨졌다면 `git show HEAD:<경로>`로 원본을 받아 복구.
- `.md` 파일은 Write로 생성해도 안전.
- 커밋·푸시는 **운영자 지시 시에만**(자동 금지) — 유일 예외: 일일 자동 발행 루틴(`docs/AUTO-PUBLISH.md`, AGENTS.md 5). 빌드는 운영자 PC/CI(`npm run build`).
- 검증: `npx tsc --noEmit`(EXIT 0) — `.next/dev` stale 에러는 `tsc 2>&1 | grep -v '^.next/'`로 src만 보거나 `rm -rf .next` 후 재실행 / `node scripts/validate-content.js`(게이트 통과) / 계산기 node 검산 / 내부링크 대상 파일 존재 확인.
- 카테고리 노출 스위치는 `src/config/categories.ts`의 `APPROVAL_MODE`(현재 true: 경제·지원금·계산기만 공개, 핫이슈·나들이·꿀팁 숨김).
- **SEO 필수(2026-07-06 전수 보정 완료 상태 유지)**: 새 페이지(page.tsx)에는 `alternates: { canonical: "/<경로>/" }`를 반드시 넣는다. 내부 링크(본문·컴포넌트)는 항상 **trailing slash**(`/tools/salary/`처럼) — no-slash는 크롤러에 308 홉을 만든다. 외부 링크는 https만.

### ⚠️ 4-1. 파이썬 일괄 수정 시 줄바꿈 규칙 (2026-08-06 사고 후 신설 — 반드시 지킬 것)

**증상**: 87편 제목을 한 번에 바꾸다가 **76개 파일이 `\r\r\n`으로 깨졌다.** git diff 가 파일당 200줄 넘게 잡혀서 발견됐다.

**원인**: `newline=""` 로 읽으면 문자열에 `\r\n` 이 **그대로 남는다.** 여기서 `newline="\r\n"` 으로 쓰면 파이썬이 문자열 안의 모든 `\n` 을 다시 `\r\n` 으로 바꾸므로 `\r\n` → `\r\r\n` 이 된다.

**규칙 — 기존 파일을 일괄 수정할 때는 바이트로 읽고 바이트로 쓴다.**
```python
raw = open(p, "rb").read()
assert b"\x00" not in raw          # NUL 검사
s = raw.decode("utf-8")
s = s.replace(old, new)
open(p, "wb").write(s.encode("utf-8"))   # 줄바꿈 변환이 일어나지 않는다
```
- **새 파일을 만들 때만** `io.open(p, "w", encoding="utf-8", newline="\n")` 을 쓴다(LF 고정).
- ❌ `newline=""` 로 읽고 `newline="\r\n"` 으로 쓰는 조합은 **절대 금지**.
- 일괄 수정 후에는 반드시 확인한다: `git diff --stat` 이 **파일당 바뀐 줄 수만큼만** 나오는가. 수십~수백 줄이 잡히면 줄바꿈이 깨진 것이다.
- 검사 스니펫: `b"\r\r" in open(p,"rb").read()` 가 하나라도 True 면 즉시 복구.

## 7. 오픈채팅 공유용 요약 (복붙)

> 새 글·가이드·계산기를 발행하면, **카카오 오픈채팅방(팁픽)에 바로 올릴 수 있는 짧은 요약**을 함께 만든다.

### 양식 (복붙 템플릿)
```
{이모지} {짧은 제목}

{핵심 한 줄 요약}

• {포인트 1}
• {포인트 2}
• {포인트 3}

👉 {URL}
#{태그1} #{태그2} #{태그3}
```

### 규칙
- **짧게** — 모바일 한 화면. 핵심 불릿 3~4개.
- 이모지 1~2개(과하지 않게), 과장·낚시 금지(신뢰 우선).
- 마지막 줄에 **URL + 해시태그**(검색 키워드 = 그 글의 핵심어).

### 예시 (양도세 가이드)
```
🏠 집 팔 때 양도소득세, 1주택이면 12억까지 비과세

집 팔 때 세금, 핵심은 '1세대 1주택 비과세' 해당 여부예요.

• 2년 보유(조정지역은 2년 거주) + 12억 이하 → 비과세
• 장기보유특별공제 최대 80%
• 다주택 중과 2026.5 부활(조정지역)

👉 tip-pick.com/guides/house-capital-gains-tax/
#양도소득세 #1주택비과세 #부동산세금
```

### ⚠️ 정보 요청 원칙
- **URL은 배포돼야 최종 확정**되고, 글마다 강조할 수치·포인트가 다르다.
- 따라서 요약을 만들기 전 **운영자에게 ① 정확한 공유 URL ② 강조하고 싶은 포인트(있으면)를 요청**한다. (가이드·계산기 경로는 알지만, 도메인 포함 최종 URL과 노출 강조점은 운영자 확인이 안전)
