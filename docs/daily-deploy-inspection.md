# 팁픽 일일 자동배포 점검 가이드

> 매일 자동배포(KST 05:23 cron) 성공 후, 새 크롤링 데이터·블로그 글이 우리가 정한
> 규칙/형식을 지켰는지, 그리고 전날 작업이 라이브에 반영됐는지 점검하기 위한 문서.
> **크롤링 주제는 매일 달라서 중간에 예상 못 한 형식/요소가 튀어나온다.** 그걸 놓치지 않는 게 목적.

---

## 사용법 (매일 아침 루틴)

1. **자동배포 성공 확인** — GitHub Actions(Deploy to Cloudflare Pages) 또는 배포 로그가 성공인지.
2. **Claude Code 새 세션을 열고**, 다음 한 줄만 지시하면 된다:
   > `docs/daily-deploy-inspection.md 읽고 오늘(2026-06-04) 기준으로 종합 점검 실행해줘.`
   - 날짜만 그날로 바꾼다. (이 파일이 레포에 있으므로 어느 세션이든 읽어서 그대로 실행 가능.)
3. **섹션별 PASS / WARN / FAIL 보고**를 받는다.
4. FAIL·의심 건이 있으면 **수정안을 먼저 확인**하고, 승인 후 수정. **빌드 검증·커밋/푸시는 내가 지시할 때만 1회.**
5. 약 **1주일간 매일** 돌린다. 안정화되면 빈도를 줄인다(주 1~2회 등).

> 핵심 규칙(절대 변하지 않음): ① 수정은 승인 후 ② 커밋/푸시는 지시 시에만 ③ 빌드 검증은 점검·수정 다 끝난 뒤 한 번만.

게이트를 통과했더라도 사람 눈으로 다시 잡아낸다. 다음을 전수 점검:

1) 블로그 글 중복 0
   - 신규 글의 제목·핵심 키워드·다루는 제도/행사명을 기존 글 전체(posts/drafts/review)와 대조.
   - 제목 표현만 다르고 같은 주제/제도면 FAIL (예: "청년 월세 20만원" vs "서울 청년월세 지원 정리").
   - 같은 축제/지원금을 날짜·연도·수식어만 바꿔 다시 쓴 글 0.

2) 지원금(benefit) 중복 0
   - 신규 benefit 제목을 기존 전체와 대조(자치구 별칭·stem 통일 반영: "용산"="용산구").
   - 같은 제도의 다른 표현 쌍 0. 의심쌍은 제목을 나란히 나열.

3) 축제/행사 중복 0
   - 같은 행사가 연도/표현만 바꿔 중복 등록되지 않았는지(같은 날짜+장소+행사명 키워드 겹침).

4) 교차 중복 점검 (benefit ↔ blog ↔ festival)
   - 같은 주제를 '동일 제목/본문 복제' 수준으로 양쪽에 올리지 않았는지.
   - (주의: 같은 지원금을 카드 + 해설 블로그로 '서로 다른 내용'으로 보강하는 건 정상.
      문제는 내용까지 사실상 복제된 경우만 FAIL.)

5) 발견 시 처리
   - 더 빈약한 쪽 삭제 + 풍부한 쪽 보존(필요 필드 이식).
   - 왜 게이트를 통과했는지 원인 분석 → dedup 임계/정규화/제도명 사전 보강안 제시.
