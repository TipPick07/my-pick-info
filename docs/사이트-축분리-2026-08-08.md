## 0. 왜 만들었나

같은 운영자가 세 도메인을 돌리는데 주제가 겹치기 시작했다. 홈 구조만 보고는 어디가 겹치는지 알 수 없어서, **세 사이트 발행물 337편을 전수 대조**해 실제 충돌을 산출했다(재현 명령 = §8).

겹침이 만드는 실제 비용은 두 가지다.

1. **같은 일을 두 번 한다.** 같은 검색어에 답하는 글을 두 도메인에 쓰면, 이겨도 자리는 하나다.
2. **권위가 분산된다.** 도메인 단위 주제 신뢰도와 링크는 도메인을 넘어 합쳐지지 않는다. 신생 도메인 3개가 각자 처음부터 쌓는다.

## 2. 채택하지 않은 진단 — 재론 방지

### ✗ "같은 주인의 다중 사이트라서 구글이 저품질 네트워크로 본다 → 애드센스 불리"

**근거가 약하고, 이 가설로 갈아타면 손해다.**

- 애드센스는 한 계정에 여러 사이트를 허용한다. 구글이 제재하는 건 *scaled content abuse*(대량 저가치 양산)와 *site reputation abuse*이지 주제가 인접한 형제 사이트가 아니다.
- ✅ **2026-08-09 GSC 3사이트 대조로 이 기각이 실측 확증됐다.** 같은 운영자·같은 작업 방식·인접 주제인데 **pension-pick만 정상**이다. 네트워크 페널티가 원인이라면 pension-pick도 막혔어야 한다.

  | | tip-pick | tipmoapick | **pension-pick** |
  |---|---|---|---|
  | 색인 / 미색인 | 37 / 1,170 | 18 / 107 | **40 / 17** |
  | **색인률** | **3%** | **14%** | **70%** ✅ |
  | 크롤됨-색인X | 568 (47%) | 20 (19%) | **0** ✅ |
  | 발견됨-색인X | 0 | 0 | 14(정상 대기) |

  → **세 사이트는 서로 다른 병에 걸려 있다.** tip-pick = 2026-06-13 자동생성 페이지 대량 삭제 후 도메인 재평가(시간 외 수단 없음) / tipmoapick = 기술 설정(아래) / pension-pick = 정상.
- tipmoapick의 노출 0 원인은 **2026-08-08 전수 실측으로 이미 확정됐다** — 87편 전부 200 OK, noindex 0건, canonical 정상, 본문 상호 중복 0쌍, 수동조치·보안문제 없음, **본문 중앙값 2,277자**. 원인은 얇은 콘텐츠다(상세 = `tipmoapick-blogger/docs/노출0-원인규명-2026-08-08.md`).
- 📌 **보완 (2026-08-09 GSC 실측 — 위 진단을 대체하는 게 아니라 각도를 하나 더한다)**: 8/8 실측은 **87편 본문 자체**를 잰 값이고, GSC는 **구글이 아는 125개 URL**을 보여준다. 둘 다 참일 수 있다. 미색인 107건의 구성은 이렇다.

  | 사유 | 건수 | 비중 |
  |---|---|---|
  | **리디렉션 오류** | **56** | **52%** |
  | 적절한 표준 태그가 포함된 대체 페이지 | 29 | 27% |
  | 크롤링됨-색인X (= 얇은 콘텐츠 신호) | 20 | **19%** |
  | 중복 페이지(표준 없음) | 2 | 2% |

  **→ 「얇은 콘텐츠」는 미색인의 19%만 설명한다. 52%는 리디렉션 오류다.**
  - 🔴 **가장 중요한 새 사실 — 42건 → 56건으로 늘고 있다.** `docs/리디렉션오류-42건-대조-2026-08-03.md`에서 이미 42건을 전수 대조했는데, 8/9 시점 **56건**이다. **원인이 규명되지 않은 채 한 달째 증가 중**이라는 뜻이다. 그 문서의 목록은 전부 **정상 발행된 본문 글**(계산기 19 + 정보글 23)이라, 라벨·아카이브 같은 자동생성 URL 문제가 아니다.
  - ⚠️ **원인 미규명**: 깨끗한 301 한 번이면 구글은 '리디렉션 포함'으로 분류하는데, tipmoapick 사유 목록에는 그 항목이 **아예 없고** 56건이 전부 '오류'다 → 체인·루프·모바일 `?m=1` 중첩 등이 겹쳐 있다. **이 세션은 egress 차단으로 실제 HTTP 응답을 확인하지 못했다.**
  - ❌ **폐기된 가설(2026-08-09, 같은 날 자체 반증) — "www/non-www 불일치"**: 브라우저 주소창에 `www` 없이 `tipmoapick.com/p/blog-page.html`로 보인 것을 근거로 "실제 사이트는 non-www인데 GSC 속성만 www"라고 적었으나 **철회한다.** 반증 3가지 — ⓐ **Chrome은 주소창에서 `www.`를 숨겨 표시하는 경우가 있다**(리디렉션의 증거가 아니다) ⓑ 저장소가 `https://www.tipmoapick.com`을 **203곳**에서 쓴다 ⓒ **8/8 실측에서 87편 전부 200 OK · canonical 87편 전부 자기 URL로 정상**이었다. 이 세 가지는 www가 정상 동작한다는 쪽을 가리킨다. **「표준 태그 대체 페이지 29건」도 www 탓이 아니라 Blogger의 `?m=1` 모바일 URL이 데스크톱 URL을 canonical로 가리키는 정상 동작으로 보는 편이 자연스럽다.**
  - 📌 **그래도 GSC 도메인 속성(`tipmoapick.com`, DNS TXT) 추가는 여전히 권장한다** — 단 "원인을 고치는 조치"가 아니라 **"www/non-www/http/https를 한 속성으로 묶어 이 논쟁 자체를 없애는 정리"**다. 지금은 URL 접두어 속성이라 어느 변형이 집계에서 빠지는지 확인할 방법이 없다.
  - ⚠️ **URL 슬러그 별건**: 한글 제목이 슬러그로 변환되지 않아 `/2026/06/2026.html`·`/2026/06/2026_01293313875.html`·`/p/blog-page_19.html`처럼 **URL에 키워드가 0**이다(`_01293313875`는 슬러그 충돌 시 Blogger 자동 부여). **단, 리디렉션 원인 확정 전에는 URL을 바꾸지 말 것** — 색인된 18편을 잃고, URL 변경 자체가 오류 원인일 수 있다.
  - ✅ **좋은 신호**: tipmoapick의 최종 크롤일은 8/3~8/5로 **구글이 지금도 활발히 크롤 중**이다(tip-pick은 홈 외 전부 6/13~16에 정지). **세 사이트 중 노력이 가장 빨리 회수되는 곳.** 작업은 `tipmoapick-blogger` 저장소에서 진행(운영자 지시, 2026-08-09).
- 실측으로 확정한 진단을 미검증 가설로 바꾸면 재신청 창을 낭비한다. 원칙 그대로다 — **원인을 정확히 짚기 전에 우회로부터 만들지 않는다.**

📌 **다만 미측정인 것 하나**: 위 「본문 상호 중복 0쌍」은 tipmoapick **내부**만 잰 값이다. **사이트 간 본문 중복은 아직 아무도 재본 적이 없다**(반증된 게 아니라 안 쟀다). §7-3에 측정 작업으로 넣었다. 주제 겹침과 문장 중복은 다른 문제이고, 후자면 진짜 위험하다.

### ✗ "네이버 블로그도 경쟁 상대다"

네이버 85편은 **구글 SERP를 두고 다투지 않는다.** 오히려 2026-08-08 실측에서 네이버의 팁모아 링크가 `nofollow`가 아님이 확인됐다 — **현재 유일한 외부 권위 신호**다. 경쟁자가 아니라 유입원으로 다룬다.

### 경계 규칙 — 겹치기 쉬운 지점만 못 박는다

- **연금·건보 주제를 tip-pick에서 다룰 때**: 「제도 소개·자격 확인」까지만 쓴다. **수령액·손익 계산은 쓰지 말고 pension-pick으로 문맥 링크**를 건다.
- **세금 주제를 tip-pick에서 다룰 때**: 「신고 절차·서류·기한」 가이드까지만. **세액 계산기는 만들지 않는다.**

## 5. 🔴 발행 전 체크 — 새 글·새 계산기를 만들 때

각 저장소의 기존 중복 체크(0단)를 **끝낸 뒤** 이 4단계를 추가로 밟는다.

1. **주제를 한 문장으로 적는다** → §3 표에서 담당 사이트를 찾는다. **담당이 아니면 그 사이트에 쓰지 않는다.**
2. 담당이더라도 **다른 두 사이트에 같은 검색어 글이 있는지 확인한다**(§8 명령).
3. 있으면 **분해 3원칙을 전부 통과해야** 쓴다. 하나라도 어기면 재탕이다.
   - **검색어가 다르다** — 두 글의 목표 검색어를 각각 적는다. **한쪽 글이 다른 쪽 검색어에도 답하면 재탕이다.**
   - **같은 주에 두 사이트에 내지 않는다** (최소 3일 간격).
   - **열위 글에서 우위 글로 링크를 건다** — 분해 글이 원본을 죽이면 안 된다.
4. **계산기는 예외 없이 한 곳에만.** §3 경계 규칙을 그대로 따른다.

> 근거: tipmoapick 실측 — 2026-07-16에 같은 주제를 양 거점 4편으로 내자 재발행 2편이 조회 1회·12회(원본 2,351회), 블로그스팟은 사이트 전체 노출이 0이 됐다. **자기잠식은 가설이 아니라 이 프로젝트에서 이미 일어난 일이다.**
