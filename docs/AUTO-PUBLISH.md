# AUTO-PUBLISH — 일일 자동 발행 루틴 SOP (2026-08-06 신설)

> **이 문서는 자동 발행 루틴의 단일 지침서(SSOT)다.** 월~토 07:00 KST 클라우드 예약 루틴이
> 이 문서를 읽고 그대로 실행한다. 글 양식은 `docs/WRITING-GUIDE.md`, 프로젝트 맥락은
> `docs/HANDOVER.md`가 SSOT이며 이 문서는 **순서와 게이트만** 정의한다(내용 중복 금지).
>
> ## 🔴 요일 게이트 (2026-08-09 운영자 확정 — 1단계보다 먼저 판정한다)
>
> | 요일 | 루틴 동작 |
> |---|---|
> | **월·화·목·금** | **정상 발행** — 아래 1~13단계 그대로 실행 |
> | **수·토** | **발행하지 않는다.** 1단계도 진입하지 말고 즉시 스킵 알림(`CTR-DAY`)만 보낸다. 커밋 없음 |
> | 일 | 루틴 없음(예약 자체가 없음) |
>
> **수·토가 CTR 보강일인 이유**: 신규 글 1편의 기대 회수는 주 0.28클릭(네이버 클릭 44 ÷ 콘텐츠 159)인데, 기존 자산 CTR +1%p는 주 +13클릭 — **약 47배**. 8/6 하루 작업(제목 87편 2절 공식)이 CTR을 2.39%→3.39%로 올려 그 주 클릭 증가분의 46%를 만든 것이 실측 근거다. 구글이 정지한 동안 회수되는 채널은 네이버뿐이므로 발행 슬롯 2개를 CTR로 돌린다.
>
> **CTR 보강 작업 자체는 루틴이 하지 않는다** — 네이버 서치어드바이저는 수동 내보내기만 가능해 루틴이 데이터에 닿을 수 없다. 운영자가 서치어드바이저 「콘텐츠 노출/클릭」을 챗에 붙이면 **대화형 세션**에서 진행한다(대상 = 노출은 많은데 CTR이 낮은 페이지 5~10개, 방법 = WRITING-GUIDE §1-8-2 제목 2절 공식).
>
> ⚠️ **예약 크론은 그대로 월~토다.** 이 게이트는 루틴이 스스로 요일을 보고 판정하는 방식이며, 크론을 바꾸지 않아도 동작한다(수·토에는 스킵 알림만 온다).
>
> **적용 범위**: 예약 실행된 자동 루틴 한정. **대화형 세션(채팅 작업)에는 적용되지 않는다** —
> 채팅 세션은 기존 규칙(커밋·푸시 = 운영자 지시 시에만) 그대로다.

## 0. 절대 규칙 (운영자 하드 룰 — 2026-08-06 확정. 무엇과 충돌해도 이것이 이긴다)

1. **중복 글 절대 금지.** 기존 글·가이드·계산기·토픽과 같은 키워드를 정면 타깃하는 콘텐츠를
   만들지 않는다(§1-7 7 카니벌라이제이션). 의심되면 만들지 않는다.
2. **추측으로 글 작성 절대 금지.** 대상·금액·날짜가 **공식 출처**(정책브리핑·부처·공단·국세청 등)
   원문에서 확인되지 않으면 그 주제는 발행하지 않는다. 뉴스 기사만으로는 근거가 되지 않는다
   (2026-08-06 소비쿠폰 보류 판정이 표준 사례 — HANDOVER §9 참조).
3. **스킵은 실패가 아니다.** 조건을 채우는 주제가 없으면 그날은 발행하지 않고 스킵 알림만 보낸다.
   억지 발행이 스킵보다 나쁘다. 주제가 바닥나는 날은 계획된 동작이다.

> ⭐ **추가 제약 (2026-08-08 신설 — 하드 룰은 위 3개 그대로, 이건 별건이다)**
> 위 3개를 다 통과해도 **주제가 tip-pick 축이 아니면 발행하지 않는다.** 운영자가 도메인 3개를
> 돌리는데 계산기 13종이 이미 정면 중복이라, 축을 벗어난 발행은 곧 자기잠식이다
> (실측 사례 = `docs/사이트-축분리-2026-08-08.md` §5 — 같은 주제를 양 거점에 4편 내자
> 재발행분 조회 1회·12회, 원본 2,351회). 집행 지점은 **2단계(후보 필터)와 5-1단계(선정 후 게이트)**.
> 판정이 안 서면 통과시키지 말고 스킵(OFF-AXIS).

**Fail-closed 원칙**: 아래 파이프라인의 어느 게이트든 실패·불확실이면 **다음 단계로 가지 않고
스킵(§4)으로 전환**한다. 자동 루틴에는 물어볼 운영자가 없다 — 보류가 곧 안전이다.

## 1. 파이프라인 (순서 고정 — 건너뛰기 금지)

### 1단계. 준비
- `git pull`로 main 최신화. 충돌·비정상 상태면 → 스킵(CONFLICT).
- 의존성: `node_modules` 없으면 `npm ci` 먼저(클라우드 새 세션은 항상 없음 — 9단계 tsc·빌드에 필요).
- `docs/HANDOVER.md` §7·§9 최근 로그 + `docs/WRITING-GUIDE.md`(특히 §1-6·§1-7·§1-8·§1-8-2·§1-8-3·§1-9)를 읽는다.
- 🔴 **`docs/사이트-축분리-2026-08-08.md`의 §3(축 배분)·§5(발행 전 체크)·§6(9/5까지 금지)을 읽는다** (2026-08-08 추가). 주제 선정의 전제이고, 2단계·5-1단계에서 이 내용을 그대로 집행한다.
- 환경 확인: node·python·git + `NAVER_CLIENT_ID/SECRET`(환경변수 또는 `.env.local`). API 불능이면 §5 폴백.

### 2단계. 주제 발굴 (HANDOVER §7 0단계)
```bash
node scripts/auto-publish/select-topic.mjs news 3
```
- 출력에서 **지원금·복지·근로/급여·육아 정책 뉴스만** 골라 후보 3~5개를 만든다(기업·지역행사·정치 기사 제외).
- 🔴 **축 필터 (2026-08-08 — SSOT §3)**: **연금·건보·노후·실버타운은 pension-pick 몫, 세금·부동산·대출 계산기는 팁모아 몫이라 후보 단계에서 뺀다.** ⚠️ 이전 판은 이 줄에 「**연금**」이 후보 대상으로 적혀 있었다 — 축 분리 확정으로 **삭제한 것이지 누락이 아니다.** 세금 주제는 「신고 절차·서류·기한」까지만 tip-pick이 쓸 수 있고 **세액 계산은 쓰지 않는다**(§3 경계 규칙). 애매하면 후보에서 뺀다.
- 후보가 부족하면 보충 순서: ① WRITING-GUIDE §1-8-1 **시즌 곡선**(이번 달 폭증 키워드) ② §1-8-1 대장의
  미다룬 인접 주제 ③ HANDOVER §8 백로그. **지역 한정 주제는 제외**(§1-8-1 — 지역 한정어는 대부분 죽는다).

### 3단계. 공식 출처 검증 (하드 룰 2)
- 후보별로 정책브리핑(korea.kr)·소관 부처·공단 **원문**을 열어 ① 시행·지급 날짜 ② 대상 ③ 금액을 확인한다.
- 원문 확인 실패 = 후보 탈락. 확정 전 정부안·추진 단계는 다룰 수 있으나 제목·본문에 "추진"·"정부안" 명시(§7 규칙).
- **전 후보 탈락 시 → 스킵(NO-SOURCE)**.

### 4단계. 키워드 실측 (WRITING-GUIDE §1-8)
```bash

```
- 후보당 표현 2~3개(제도 공식명/생활어/상위어)를 실측한다. 출력의 `normalized`가 기준어(실업급여)=100 상대값 —
  §1-8-1 대장과 직접 비교 가능.
- **판정(최대 표현 기준)**: `normalized ≥ 5` 통과 / `1~5` 는 최근 30일 내 확정·시행된 **신설·개편 제도만** 통과
  (검색량이 아직 안 붙은 새 제도 예외) / `< 1`·`no-data` → 후보 탈락. **전 후보 탈락 시 → 스킵(NO-VOLUME)**.

### 5단계. 중복 체크 (하드 룰 1)

### 12단계. 배포 검증
- 푸시 후 GitHub Actions(`deploy.yml`)가 자동 빌드·배포한다(Cloudflare Pages).
- ⚠️ **(2026-08-07 실측) `on: push` 런 생성이 30분 가까이 지연될 수 있다.** 루틴 푸시 2건 모두 워크플로는 정상 생성됐으나 **커밋 후 27~30분 뒤**였다(22:25:52→22:55:53 / 22:45:33→23:12:36 UTC). 푸시 주체·토큰 문제가 아니다. 따라서 **15분 폴링에서 200이 안 나오면 스킵하지 말고, 그때 `deploy.yml`을 `workflow_dispatch`로 트리거하고 5분 더 폴링한다**(GitHub MCP `actions_run_trigger` / ref=main — 트리거 후 약 2분이면 배포된다). 그래도 200이 아니면 그때 '배포 미확인'으로 알린다.
- **새 글 라이브 URL**(`https://tip-pick.com/blog/<slug>/`)을 60초 간격으로 최대 15분 폴링 → HTTP 200 확인.
- 15분 내 200 미확인 → 알림에 **"⚠️ 푸시됨·배포 미확인(Actions 확인 필요)"** 명시. prebuild `--quarantine`이
  새 글을 격리하면 배포는 성공해도 글이 없을 수 있다 — 그래서 이 단계는 생략 금지.

## 3. 알림 양식 (클라우드 앱 알림 = 루틴 최종 메시지)

**발행일:**
```
✅ 자동 발행 완료 — <글 제목>
글: https://tip-pick.com/blog/<slug>/ (라이브 ✅)
짝: <가이드|계산기|없음> <URL>
근거: <뉴스·공식 출처 기관명> / 실측 <키워드> <normalized>(실업급여=100)
축: <담당 축> / 타 사이트 동일 검색어 <건수> (5-1단계 통과 근거)
자체 계산: <핵심 수치 한 줄>
💬 오픈챗 문구:
<WRITING-GUIDE §7 양식 완성본>
```

**스킵일:**
```
⏭️ 오늘 자동 발행 없음 — <사유 코드>: <한 줄 설명>
검토한 후보: <후보별 탈락 사유 1줄씩>
```
**(2026-08-09) 알림에서 「색인 요청 몫(5)」 줄이 삭제됐다** — 구글 색인 요청 루틴 중단(근거·실측 = `docs/INDEXING-QUEUE.md` 상단). 스킵일에 INDEXING-QUEUE 몫을 기입하던 커밋도 함께 폐지한다. 스킵일에는 **커밋 없이 알림만** 보낸다.

## 4. 스킵 사유 코드

| 코드 | 뜻 |
|---|---|
| NO-TOPIC | 뉴스·시즌·백로그 전부에서 유효 후보 0 |
| NO-SOURCE | 후보는 있으나 공식 출처 원문 확인 전멸 (하드 룰 2) |
| NO-VOLUME | 실측 전멸 — normalized < 1 또는 no-data (§1-8) |
| DUP | 중복 리스크로 전 후보 탈락 (하드 룰 1) |
| OFF-AXIS | 3사이트 축 분리에 걸려 전 후보 탈락 (5-1단계 — SSOT §3·§5) |
| GATE-FAIL | 9단계 검증 게이트 실패(2회 수정 후에도) |
| CTR-DAY | **수·토 = 네이버 CTR 보강일** (요일 게이트 — 문서 상단). 발행하지 않는 것이 정상이며 실패가 아니다 |
| CONFLICT | git pull 충돌·저장소 비정상 |
| API-DOWN | 네이버 API 불능 + §5 폴백으로도 실측 불가 |

## 5. 폴백 (API 불능 시 — 그래도 하드 룰은 그대로)

- **스크립트가 403(egress 차단)으로 실패** → 먼저 카카오 PlayMCP의 NaverSearch MCP 도구(`datalab_search`·`search_news`)로 같은 실측·스캔을 시도한다(MCP는 서버 경유라 샌드박스 egress와 무관). 기준어 동봉·정규화 규칙(§1-8)은 스크립트와 동일하게 적용.
- **뉴스 API 불능** → WebSearch + 정책브리핑(`korea.kr` 보도자료) 직접 열람으로 2단계 대체.
- **데이터랩 불능** → §1-8-1 실측 대장으로 4단계 대체. **대장에 없는 신규 키워드는 실측 불가 = 원칙 스킵.**
  예외는 공식 확정된 신설 제도뿐이며, 이 경우 알림에 **"실측 미완"**을 반드시 표기한다.
- **dedup 스크립트 불능** → `grep -rl` 전수 + WRITING-GUIDE §6 현황 목록 수동 대조.
- 폴백으로도 판단 근거가 안 서면 → 스킵(API-DOWN). 추정으로 메우지 않는다.

## 6. 운영자 개입 포인트 (사람이 하는 일)

- **아침 확인**: 알림 확인 → 오픈챗 문구 게시. **(2026-08-09) 「GSC·네이버 색인 요청 5건」은 삭제됐다** — 구글 색인 요청 중단(`docs/INDEXING-QUEUE.md` 상단). 네이버 수집 요청은 발행·대변경 시에만 병행(매일 몫 없음).
- **잘못된 글 회수**: `git revert <커밋> && git push` 한 번 → Actions가 재배포(정적 사이트라 즉시 원복).
- **하루 쉬기 / 중지**: 예약 루틴 일시정지(claude.ai 예약 작업 화면). 재개도 같은 곳.
- **규칙 변경**: 이 문서를 고치면 다음 실행부터 반영된다(루틴은 매회 이 문서를 새로 읽는다).
- **수·토**: 루틴은 `CTR-DAY` 스킵 알림만 보낸다. 운영자가 네이버 서치어드바이저 「콘텐츠 노출/클릭」을 챗에 붙이면 대화형 세션에서 제목·설명 CTR 보강 진행.
- **일요일**: 루틴 없음 — 주간 리포트 분석·다음 주 방향 결정(HANDOVER §7). **(2026-08-09) 「재신청 게이트 판정」은 여기서 삭제됐다** — 주간 판정 폐지, 월 1회 「구글 신뢰 3종」으로 대체(`MONETIZATION-ROADMAP.md` §1).
- **계산기 수시 발행·보강·통폐합** 등 판단이 필요한 작업: 기존처럼 대화형 세션에서.
